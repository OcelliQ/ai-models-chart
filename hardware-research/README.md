# Minimum hosting research checkpoint

Resume from `state.json` and each group’s `input.json`. Research agents own their group directory and write one result JSON per model using a temporary file followed by an atomic rename. Existing complete results are checkpoints and must be read before continuing. The consolidated dataset, renderer, and hardware configuration live in the repository root.

The research estimates record one 108K-token session with approximately 4-bit or higher precision and the complete unpruned model resident in GPU or unified memory. Lookup tables count toward resident memory. Disk streaming, expert pruning, and lower-bit demonstrations do not establish a qualifying minimum. Use primary model cards and deployment measurements, and preserve uncertainty when evidence is incomplete. The approved chart policy in `../hosting_tiers.json` budgets 4 / 8 / 16 concurrent sessions in the higher tiers, sharing weights and adding nominal context/runtime headroom to the saved single-session estimates.

Each group also saves `parameter_counts.csv`, separating sourced parameter counts from estimated hosting memory. `../collect_parameter_counts.py` consolidates these into `../model_parameters.csv` without assigning any hardware costs. The CSV retains source URLs, count confidence, and backbone/lookup decomposition where available. Count all experts and lookup tables, rather than only parameters activated per token.

The user approved a roughly indicative parameter-to-cost fallback using Kimi K3 as the high-end example and requested reasonable parallelism from larger desktop clusters onwards. `../hosting_tiers.json` is the active policy; `state.json` preserves the original proposal and implementation progress. `../build_hardware.py` builds a hosting sidecar without rewriting prices or intelligence scores in `models.csv`. Parameter count confidence and hosting confidence remain separate; costs and session budgets are estimates. See `../README.md` for the policy, current coverage, caveats, regeneration commands, and validation.
